# 空压站智能调度项目：四人协作任务与验收指标

## 成员 A：数据处理、负荷预测与健康诊断

### 具体任务

1. 整理主办方提供的所有数据文件，完成字段、单位和时间戳统一。
2. 处理缺失值、重复值、异常值和时间断点，形成标准数据集。
3. 建立用气负荷预测模型，预测未来 15、30、60 分钟的用气流量。
4. 建立设备健康诊断模型，根据振动、温度、电流和运行时间输出健康指数。
5. 输出异常设备、异常因素、风险等级和维护建议。
6. 向成员 C 提供可直接调用的预测与诊断函数。

### 验收指标

- 数据文件均有明确字段说明和单位说明；
- 数据清洗过程可重复执行；
- 负荷预测 MAPE 目标不高于 8%；
- 单次负荷预测时间不高于 10 秒；
- 能输出 0～100 的健康指数；
- 能正确识别预设的振动、温度和电流异常场景；
- 输出结果包含异常原因和处理建议；
- 模型测试严格按照时间顺序划分数据，不发生未来数据泄漏；
- 没有真实标签时，指标必须标记为仿真或无监督验证。

---

## 成员 B：人工基线、多机调度优化与喘振预警

### 具体任务

1. 建立传统人工调度基线，包括固定启停顺序和压力阈值控制。
2. 建立各机组的流量、功率、加载率和效率计算模型。
3. 实现最优开机组合、负荷分配和压力设定值优化。
4. 加入供气需求、备用容量、加载范围、启停次数和最小运行时间约束。
5. 将设备健康风险纳入调度，异常设备自动限载或退出运行。
6. 根据喘振边界计算安全裕度，输出低、中、高三级风险。
7. 输出人工方案与智能方案的能耗、压力、启停和加载率对比。
8. 向成员 C 提供可直接调用的调度与喘振评估函数。

### 验收指标

- 调度方案总供气量满足预测需求和备用容量要求；
- 所有机组加载率均处于允许区间；
- 单次调度方案生成时间不高于 30 秒，完整决策不高于 60 秒；
- 优化方案相对人工基线的模拟综合能效提升目标不低于 6%；
- 加载率偏离度目标不超过 ±10%；
- “大马拉小车”工况时长下降目标不低于 60%；
- 供气压力合格率目标不低于 99.5%；
- 喘振预警能够区分低、中、高风险；
- 高风险方案不得通过安全校验；
- 求解失败或数据不足时能够返回安全回退方案；
- 所有节能指标必须由同一测试数据上的基线对比计算。

## 成员 C：后端、MCP、Agent与模拟控制

### 具体任务

1. 建立项目公共数据格式、后端服务和数据库。
2. 接入成员 A 的负荷预测与健康诊断模块。
3. 接入成员 B 的调度优化与喘振预警模块。
4. 实现设备状态、历史查询、预测、诊断、调度和报告接口。
5. 建立负荷预测、调度优化、健康诊断、喘振预警和控制指令 5 个 MCP 服务。
6. 实现自然语言 Agent，能够理解用户需求并调用正确工具。
7. 实现模拟 SCADA、PLC 和工单接口。
8. 实现控制指令安全检查、人工确认、执行反馈和失败回退。
9. 完成 Docker 部署及 COSMO Code 平台适配。

### 验收指标

- 5 个 MCP 服务均能被独立调用；
- 后端接口输入输出符合统一数据格式；
- Agent 能完成至少 10 轮连续对话；
- 自然语言意图识别准确率目标不低于 90%；
- 能完整处理“3号机振动偏高，请重新调度”场景；
- 控制指令生成时间不高于 5 秒；
- 模拟指令下发时间不高于 3 秒；
- 模拟执行反馈时间不高于 10 秒；
- 未经人工确认的控制指令不得执行；
- 安全校验失败的方案不得生成可执行指令；
- 重复确认不会导致重复执行；
- Docker 环境能够一键启动，服务健康检查正常。

## 成员 D：前端可视化、系统测试与比赛材料

### 具体任务

1. 建立运行总览页面，展示压力、流量、功率和机组状态。
2. 建立负荷预测、调度方案、健康趋势、喘振风险和能效分析页面。
3. 建立 Agent 对话、控制确认、告警事件和执行日志页面。
4. 展示人工调度与智能调度的优化前后对比。
5. 实现实时数据、历史数据、预测数据和仿真数据的明确标识。
6. 制作两个可重复演示的场景：负荷下降节能调度、设备异常安全重调度。
7. 完成端到端测试、演示流程测试和异常状态测试。
8. 整理方案书、技术报告、PPT、视频脚本和答辩材料。

### 验收指标

- 所有核心页面均可正常访问和刷新；
- 页面能够正确显示压力、流量、功率、加载率和风险等级；
- 图表单位、时间和设备编号与后端数据一致；
- 人工方案与优化方案的指标对比清晰可见；
- 真实、预测和仿真结果不会混淆；
- 安全校验失败时，页面必须禁用执行操作；
- 两个典型场景均可一键启动、重置和重复演示；
- 主要页面在常见桌面分辨率下无明显错位或内容溢出；
- 接口失败、空数据和加载中状态均有明确提示；
- 5～10 分钟演示视频流程能够完整跑通；
- 方案书不少于 20 页；
- PPT、技术报告和测试结果中的指标口径保持一致。

## 团队共同验收标准

项目最终必须完整跑通以下流程：

```text
读取实时状态
→ 预测未来负荷
→ 诊断设备健康
→ 生成多机调度方案
→ 校验喘振和供气安全
→ Agent解释决策
→ 用户人工确认
→ 模拟下发控制指令
→ 返回执行结果
→ 保存决策与执行日志
```

最终共同指标：

- 完整调度决策周期不高于 60 秒；
- 系统具备人工调度和智能调度对比；
- 所有关键调度结果都有原因说明；
- 所有控制操作都经过安全校验和人工确认；
- 两个典型场景能够连续、稳定地完成演示；
- 真实验证、历史回测和仿真验证必须明确区分；
- 四个模块合并后能够通过统一的端到端测试。
